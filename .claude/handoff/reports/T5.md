# T5 交付报告

## 结论

T5 的独立 PP-OCRv6 正文融合代码、对齐统计、校准集和离线重算产物已保留。本轮只处理 2026-10-09 中期审核的 4 个阻断项：为 assemble/ingest 脚本测试夹具补齐显式公式 run 与最小独立 OCR run，23 个失败全部修复；补写本报告；排除第三方 PDF 派生裁剪图；全部 T5 交付纳入一次提交。

本次没有 ingest、publish、修改 `data/registry/` 或覆盖正式 Canonical，也没有重新运行/下载 OCR 模型、调用外部 LLM、修改准入或 `usage_policy`。

## 做了什么

1. `scripts/assemble_corpus_v2.py` 在统一 assemble 入口接收独立 OCR run-id，并从 `--root` 下读取公式缓存和独立 OCR run；OCR 页缺 run 或缺页时显式硬失败。
2. `src/ingestion/independent_ocr_fusion.py` 对 OCR 路由页执行几何和文本对齐，只对正文 text region 应用 `t5-calibrated-v1`：非噪声、PP score >= 0.97；替换还要求 alignment >= 0.72、有效字符不减少、宽度比 <= 1.25。表格、公式、图片区域不改。
3. 融合元素保留 engine、run-id、run manifest SHA-256、原主 OCR 文本、独立 OCR 文本、对齐分数、规则版本和来源 region；质量维持 `needs_review`。阅读顺序按 y/x 重排，ID 输入规则未改。
4. 中期审核的 23 个失败来自测试临时根没有匹配默认公式 run，也没有独立 OCR 页。`tests/test_t06_pipeline_scripts.py` 现显式传入测试 run-id，并按夹具 OCR 页写入身份、页码和坐标一致的最小独立 OCR 结果。没有跳过测试、修改原断言或放宽失败语义。
5. `.gitignore` 新增 `eval/audits/ocr_fix/T5_calibration_crops/`；该目录仍留在本地，不纳入提交。

## 已知限制

- 独立 OCR run 是显式本地依赖；OCR 路由页缺 run/缺页会硬失败。这是预期的 fail-closed 行为。

- 所有融合元素仍为 `needs_review`；没有质量放行或法规内容权威核验结论。
- 201 样本这里只完成自动重匹配和变化统计；T6 尚需按原图做样本外质量判定。
