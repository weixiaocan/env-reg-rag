# T1 OCR 文本按文档抽样核对表（只生成工作表，不做判定）

## 背景与目标
当前语料 `corpus-0b9a1fd84e3d`（4232 chunks）中 3201 个是 `source_locator_only`。其中 2541 个来自 10 份扫描件：OCR 正文一律被 `canonical_assembly.py::_derive_text_quality` 判为 `needs_review`（reason `ocr_source_review`），这 10 份文档 answer 块为 0。

负责人已选定方案 C：**按文档抽样核对 OCR 质量，达标的文档整体放开 OCR 正文用于回答**。T1 只负责产出可复现的抽样工作表和原图截图，供 T2 由 Codex 与 Claude **各自独立**判定。T1 不做任何判定。

## 范围
1. **先调查已有资产再写代码**：`scripts/run_independent_ocr_verification.py`、`src/evaluation/independent_ocr_verifier.py`、`data/model_runtime/independent_ocr/`、`src/adapters/pdf_region_renderer.py`、`scripts/scan_canonical_text_quality.py`。说明它们是否已运行过、产物在哪、能否复用（例如独立 OCR 引擎的比对结果可作为 T2 的第三信号）。能复用就复用，不重复造轮子。
2. 新增脚本 `scripts/build_ocr_sample_sheet.py`（逻辑放 `src/evaluation/ocr_sampling.py`，脚本只做 CLI）：
   - 输入：当前正式指针对应的语料版本（从 `data/registry/corpus-current.json` 读取，不硬编码），只读取本地 canonical 产物 / chunk 数据，**只读**访问 Qdrant 也可，但不写。
   - 抽样总体：每份文档中，`usage_policy=source_locator_only` 且**唯一阻断原因**属于 OCR 来源类（`ocr_source_review` / `needs_review_source`，可附带 `too_short`）的**纯 text** chunk。含 table/formula/figure 元素、`quarantined`、`mojibake`、`unreadable` 等其他原因的 chunk 不进入本次抽样，按原因计数写入汇总。
   - 抽样方法：每份文档固定随机种子（如 `sha256(doc_sha + "ocr-sample-v1")`）抽 25 个；按物理页分层（尽量覆盖文档前中后段）；总体不足 25 的全取。结果必须可复现。
   - 每个样本输出：`sample_id`、文档名、文档 sha256、`chunk_id`、物理页码、各页 bbox（来自 source_spans）、chunk 全文（与入库正文逐字一致）、截图路径、截图 sha256、阻断原因列表。
   - 截图：对 chunk 在每页的 span 并集 bbox 外扩少量边距、200dpi 裁剪 PNG；跨页 chunk 每页一张。存到 `eval/audits/ocr_sampling/crops/`。若裁剪失败，记录失败原因，不得静默跳过。
   - 输出：`eval/audits/ocr_sampling/sample_sheet.jsonl`、`sample_summary.json`（每文档总体数、抽样数、排除原因计数、种子、语料版本、生成时间、脚本 git commit）以及一页 `README.md`（说明判定标准，见下）。
3. 在 `README.md` 写入 T2 的判定标准（固定下来，T2 双方都照此判）：
   - `exact`：与原图一致（忽略空白、换行）。
   - `minor`：仅标点/全半角/空格/版式差异，不影响任何数字、单位、条款号、术语与语义。
   - `error`：任何数字、单位、符号、条款编号、关键词错误；错字导致词义变化；漏字/多字超过一个短语；串行/串栏导致语义错误。
   - `unjudgeable`：截图不清或裁剪错误，需写原因。
   - 文档准入门槛（T2 汇总时使用）：可判定样本中 `error` 占比 ≤ 1/25 且 Wilson 95% 下界报告在案；`unjudgeable` > 3 的文档不作结论。
4. 测试：为抽样的确定性（同输入同输出）、总体筛选规则、bbox 并集、跨页、总体不足 25 的情形写单元测试，用合成数据，不依赖真实 PDF。
5. 实际运行一次脚本，生成真实工作表和截图。

- 每个样本截图存在、sha256 与表中一致；chunk 文本与入库正文逐字一致（写一个核验步骤并在报告中给出核验结果）。
- 重跑脚本输出字节一致（证明可复现），报告给出两次运行的哈希。
- 新增测试和完整 pytest 结果原文写入报告。
- 完成后提交一次（英文提交信息，末尾 `Co-Authored-By: Codex <noreply@openai.com>`）；截图 PNG 若总大小 > 30MB，不提交截图，只提交 jsonl/summary 并在 `.gitignore` 中排除 crops，报告说明。
