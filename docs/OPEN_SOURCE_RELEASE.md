# 开源发布边界与复现说明

## 1. 发布内容

公开仓库包含项目源代码、测试、规格与架构文档、来源登记、人工审核过的问题集，以及不含受限全文的评估结论。它用于展示和复现排水规范证据型 RAG 的工程流程。

公开仓库不包含以下本地资产：

- `data/raw/` 中的原始 PDF；
- `data/canonical/` 中的全文解析结果；
- `data/evidence/` 与 `data/retrieval/` 中可还原原文的证据和检索块；
- `data/eval_results/` 中的 OCR 全文、页面渲染图和模型运行明细；
- `.env`、查询日志、SQLite 运行库、向量库与备份。

这些内容被 `.gitignore` 明确排除。即使某份 PDF 可以从政府网站公开下载，也不据此推断本项目拥有重新分发全文的权利。

## 2. 本地语料准备

1. 查看 `data/registry/document_reviews.csv` 中已核验的文档标题、官方来源 URL、状态和校验结论。
2. 由使用者自行从官方来源下载文档，放入 `data/raw/`。
3. 运行 `python scripts/data_inventory.py`，生成本地清单与 SHA-256。
4. 对照来源登记复核文件名、标准号、效力状态和哈希；不要把“可下载”误标为“允许再分发”。
5. 按 README 的 M1-M3 命令生成登记库、解析结果、证据单元和 Qdrant 索引。

部分实验文档没有已核验的官方全文 URL，因此不能仅凭仓库元数据自动下载。缺少对应文档时，相关全链路测试和演示不可复现；这属于公开语料边界，不应通过上传来源不明的副本绕过。

## 3. 许可证路线

项目保留 PyMuPDF 1.28.2 作为有文字层 PDF 的主解析路径，因此项目代码采用 `AGPL-3.0-only`。通过网络向用户提供修改后的版本时，需要特别检查 AGPL 第 13 节的对应源码提供义务。

直接依赖和独立运行组件的许可清单见根目录 `THIRD_PARTY_NOTICES.md`。该清单不构成法律意见，也不替代发布具体 Docker 镜像时对完整依赖闭包和系统包的复核。

## 4. Git 历史策略

开发阶段的旧历史曾包含原始 PDF、疑似 API Key 和个人标识。公开版不保留这些旧提交，而是从通过公开树检查的当前工作树建立新的根提交。旧历史只保存在公开仓库之外的本地备份中。

发布前必须对新历史重新执行以下门控：

- 不存在 PDF 或 Office 文档 blob；
- 不存在 `.env` 或非占位 API Key；
- 不存在个人姓名、本机用户名或绝对路径；
- 不存在被 `.gitignore` 排除的派生全文与运行数据。

## 5. 当前边界

本项目已验证的是可演示、可评估、可恢复的单机 POC。开源发布不代表生产就绪，也不代表对政策、标准效力或工程合规结论作担保。
