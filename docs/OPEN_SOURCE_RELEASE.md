# 开源发布边界与复现说明

## 1. 发布内容

公开仓库包含项目源代码、测试、规格与架构文档、来源登记、人工审核过的问题集、评估结论，以及 `data/raw/` 下的全部 27 个原始 PDF 文件。它用于展示和复现环保法规规范证据型 RAG 的工程流程；资料库可按相同门控持续扩展。

PDF 盘点口径如下：

- 27 个仓库 PDF 文件，共 1252 页；
- 22 个独立文件内容；
- 23 份原候选语料；
- 4 份位于 `_official_verification/` 的官方核验副本；
- 5 个 SHA-256 完全重复副本，保留以记录原始候选与官方核验关系。

公开携带、文档准入和正式回答语料发布是不同概念。27 个文件随仓库提供，不表示它们全部通过来源、版本、效力、解析质量或正式语料门控；当前正式回答语料仍以版本化 manifest 为唯一依据。

公开仓库不包含以下可重建或运行期资产：

- `data/canonical/` 中的全文解析结果；
- `data/evidence/` 与 `data/retrieval/` 中可还原原文的证据和检索块；
- `data/eval_results/` 中的 OCR 全文、页面渲染图和模型运行明细；
- `.env`、查询日志、SQLite 运行库、Qdrant 数据与备份、模型缓存和其他运行数据。

这些内容被 `.gitignore` 明确排除；`data/raw/**/*.pdf` 则被显式允许进入 Git。PDF 来自公开网络渠道，但“公开可取得”不等于本项目已经取得再分发授权，学习、研究或非商业用途也不能替代授权。具体权利边界和下架机制见根目录 `DATA_NOTICE.md`。

## 2. 本地语料与派生产物准备

1. 克隆仓库后核对 `data/raw/` 与 `data/registry/inventory.csv`；无需另行下载当前 27 个 PDF。
2. 运行 `python scripts/check_public_release.py`，检查数量、SHA-256、重复关系、Git 包含/排除策略和公开树卫生。
3. 如需重新生成盘点表，运行 `python scripts/data_inventory.py`，并审查任何数量、页数、哈希或关系变化。
4. 查看 `data/registry/document_reviews.csv` 中已核验的文档标题、官方来源 URL、状态和校验结论；不要把“可下载”或“仓库已携带”误标为“允许再分发”或“已批准正式语料”。
5. 按 README 的 M1-M3 命令生成本地 SQLite 登记库、解析结果、证据单元和 Qdrant 索引。

部分实验文档仍没有已核验的官方全文 URL，或来源、版本、效力状态尚待复核。仓库携带这些文件不会自动提高其准入状态，也不得绕过正式语料发布门控。

## 3. 许可证路线

项目保留 PyMuPDF 1.28.2 作为有文字层 PDF 的主解析路径，因此项目自行编写的代码和文档采用 `AGPL-3.0-only`。通过网络向用户提供修改后的版本时，需要特别检查 AGPL 第 13 节的对应源码提供义务。

AGPL 不自动覆盖或授权第三方 PDF。项目不出售 PDF，也不授予其商业使用权。PDF 权利、SHA-256 的证明边界、下架流程和贡献限制由 `DATA_NOTICE.md` 单独说明。

直接依赖和独立运行组件的许可清单见根目录 `THIRD_PARTY_NOTICES.md`。该清单不构成法律意见，也不替代发布具体 Docker 镜像时对完整依赖闭包和系统包的复核。

## 4. Git 历史策略

开发阶段的旧历史曾包含原始 PDF、疑似 API Key 和个人标识。公开版不保留这些旧提交，而是从通过公开树检查的当前工作树建立新的根提交。旧历史只保存在公开仓库之外的本地备份中。

发布前必须对新历史重新执行以下门控：

- 只存在 `data/raw/**/*.pdf` 中与 `inventory.csv` 一致的 27 个 PDF blob，不存在其他 PDF 或 Office 文档 blob；
- 不存在 `.env` 或非占位 API Key；
- 不存在个人姓名、本机用户名或绝对路径；
- 不存在被 `.gitignore` 排除的派生全文与运行数据；
- `DATA_NOTICE.md` 存在，且公开树检查通过。

执行门控：

```powershell
python scripts/check_public_release.py
```

## 5. 当前边界

本项目已验证的是可演示、可评估、可恢复的单机 POC。开源发布不代表生产就绪，也不代表对政策、标准效力或工程合规结论作担保。
