# 排水规范证据助手——界面决策标准

状态：Draft 0.1  
日期：2026-09-03

本文只定义本项目选择界面模式时的评判标准，不预设前端框架，也不等同于竞品调研结论。

## 核心用户任务

用户需要在一次查询中完成：提出问题、理解受证据约束的回答、识别不确定性、检查关键主张对应的原文、确认文档版本与适用范围，并在必要时修正条件或转人工判断。

## 决策优先级

| 优先级 | 标准 | 判断问题 |
| --- | --- | --- |
| 1 | 主张与证据对应清楚 | 用户能否从答案中的一个主张直接打开支持它的证据，而不是去来源列表里猜？ |
| 2 | 原文可核验 | 证据是否展示足够上下文，并能定位到文档版本、章节/条款和页码？ |
| 3 | 适用性可见 | 地域、时间、文档状态和适用对象是否与证据一起出现？未知信息是否明确标记？ |
| 4 | 不确定性与拒答清楚 | 条件不足、证据冲突或未收录时，界面是否说明缺什么以及下一步怎么做？ |
| 5 | 阅读负担可控 | 默认视图是否突出答案和关键证据，同时允许按需展开完整原文与元数据？ |
| 6 | 查询可修正 | 用户能否补充时间尺度、地域、文档范围等条件，并理解当前筛选状态？ |
| 7 | 反馈可用于改进 | 用户能否针对错误答案、错误引用、遗漏证据或版本问题给出结构化反馈？ |
| 8 | 查询可复现 | 是否能识别本次查询使用的语料版本，并支持复查历史结果？ |

## 不采用的表面指标

- 不以“像聊天软件”作为先进界面的判断标准。
- 不以动画、卡片数量或 Dashboard 页面数量证明企业级能力。
- 不把来源集中列在回答末尾视为已经建立主张—证据映射。
- 不用模型生成的摘要替代可回查原文。
- 不让调试分数和内部检索参数占据普通用户的主界面。

## POC 约束

首期界面必须证明核心证据闭环，但不要求完成复杂账户、权限、协作和移动端能力。任何候选模式都应能够在面试演示中清楚展示正常回答、条件不完整、证据不足和版本/地域冲突至少四类状态。
