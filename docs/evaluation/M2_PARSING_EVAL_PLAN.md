# M2 PDF 解析实验与质量评价计划

## 1. 所在阶段与目的

本计划对应项目看板的 M2“PDF 解析/OCR 与统一文档模型”。它位于文档登记之后、检索索引之前。

M2 只回答两个问题：

1. 每一页应走原生解析、局部/整页 OCR，还是空白跳过？
2. 解析结果能否保留后续证据检索所需的文字、条款、表格和原文位置？

本阶段不比较向量数据库，不优化召回，不生成回答，也不把实验样本自动升级为正式语料。

## 2. 固定代表页面集 v0

页面集记录在 `data/registry/m2-page-sample-v0.csv`，由 8 份已批准实验文档中的 40 个 PDF 物理页组成。

| 页面类别 | 数量 | 用途 |
| --- | ---: | --- |
| 可读原生文字候选 | 14 | 检查 PyMuPDF 是否能保留阅读顺序、条款、表格和坐标 |
| 坏文字层/乱码候选 | 7 | 防止把“存在字符对象”误判成“文字可用”，比较原生提取与 OCR |
| 全扫描 OCR 候选 | 17 | 检查正文、表格、公式、流程图和水印条件下的 OCR 能力 |
| 空白负样本 | 2 | 验证空白页应跳过，而不是因为零文字直接触发 OCR |
| 合计 | 40 | 满足技术方案中 30～50 个代表页的实验范围 |

`route_hypothesis` 是实验前假设，不是最终标签。只有完成基线输出和人工复核后，才能批准页面路由规则。

## 3. 为什么不能只检查“有没有文字层”

页级探测与视觉检查已经发现：

- `QX/T 489-2019` 的正文视觉清楚，但当前提取结果包含大量 `/G21` 一类字体编码标记。
- `GB 55027-2022` 的正文视觉清楚，但当前提取主要得到乱码和水印对象。
- 两份文档包含真正的视觉空白页，零文字不能直接等价为“需要 OCR”。
- 扫描文档中同时存在表格、公式、流程图、水印和跨页续表，单纯字符数量无法判断结构质量。

因此页面路由必须同时看文字可读性、视觉内容、结构保真和噪声，而不是使用单一字符数阈值。

## 4. 人工基准标注

AI 先为 38 个非空白页面生成候选锚点；从中固定约 20 个条款/文字锚点和 10 个表格/数值锚点作为人工基准。人工只负责确认或纠正这约 30 个重点锚点，不需要逐页、逐字标注全文。

### 4.1 每页必填项

| 字段 | 含义 |
| --- | --- |
| `sample_id` | 与固定页面清单一致的稳定编号 |
| `physical_page` | PDF 从 1 开始的物理页码 |
| `display_page_label` | 页面印刷页码；没有则记 `none`，不能用物理页码猜测 |
| `is_blank` | 视觉上是否为空白页 |
| `route_hypothesis` | 实验前的 `native_candidate`、`hybrid_candidate`、`full_ocr_candidate` 或 `blank_skip_candidate` |
| `approved_route` | 实验后批准的 `native`、`hybrid_ocr`、`full_ocr`、`skip_blank` 或 `quarantine` |
| `route_reason` | 最终批准该路径的可观察原因 |

### 4.2 非空白页锚点

- 文字页：可使用跨页面上、中、下位置的短文本锚点，但必须明确标为“片段”，不得把改写或摘要当作原文。
- 条款页：至少 1 个条款号、完整正文和所属标题路径；选中整条时必须逐字保留全部正文，不得省略限定条件或上下文。
- 表格页：优先完整还原选中表格的表名、表头、合并单元格层级、全部行名、数值、单位、总分和脚注。表格过大时可明确选定连续行列范围，但该范围内仍须完整还原，不能只摘数值。
- 公式页：公式编号、变量、上下标/符号和紧邻的变量解释。
- 图或流程图页：图名、节点文字和正文引用；M2 不要求恢复完整图语义。
- 所有锚点记录物理页；用于引用的锚点还记录 bbox，坐标统一为页面左上角原点。

## 5. 评价维度

| 维度 | 检查内容 | 记录方式 |
| --- | --- | --- |
| 页面路由 | 是否正确选择原生、OCR、跳过或隔离 | 与人工批准路径逐页比较 |
| 文字正确性 | 锚点是否缺字、错字、乱码或重复 | 锚点级正确/错误 + 字符错误说明 |
| 阅读顺序 | 标题、正文、双栏或图文顺序是否正确 | 页面级通过/失败 + 首个错序位置 |
| 条款结构 | 章、节、条、款、项及父子关系是否保留 | 锚点路径精确匹配 |
| 表格结构 | 表名、表头、行列、合并单元格、单位、脚注是否保留 | 单元格锚点 + 结构错误类型 |
| 原文定位 | 物理页、印刷页码和 bbox 能否回到原文 | 页码精确匹配；bbox 叠加图人工检查 |
| 噪声控制 | 水印、页眉页脚、乱码和重复层是否污染正文 | 噪声类型和是否影响证据 |
| 完整性 | 有内容页是否被静默解析为空，跨页内容是否丢失 | 页面级完整/部分/失败 |
| 资源表现 | 每页耗时、峰值内存、是否使用 GPU | 实测记录，不预设生产指标 |

## 6. 硬门控与阈值规则

以下情况无论总分如何都不能进入后续检索：

1. 有内容页面被静默解析为空。
2. 文字不可读或乱码，却被标记为原生解析质量通过。
3. 引用页码无法回到原 PDF 页面。
4. 条款号与正文发生错误绑定。
5. 数值与表头、单位或统计时段分离。
6. 水印或页眉页脚被当成主要证据正文。

字符正确率、结构准确率、bbox 偏差和资源阈值在人工锚点与三个最小基线实际跑完后确定。本计划不提前伪造通过率或性能数字。

## 7. 基线实验顺序

1. 保存 PyMuPDF 原生 `text`、`blocks`、`dict/rawdict` 和页面渲染结果。
2. 运行页面质量检查，记录为何通过、降级或隔离。
3. 仅对降级候选运行 PaddleOCR PP-StructureV3，不对整批文档无条件 OCR。
4. 用 Docling 对条款层级、复杂表格和阅读顺序页面做对照，不默认进入正式依赖。
5. 将各工具输出归一化为同一 Canonical Document 草案。
6. 生成逐页比较报告和 bbox 叠加图，由人工确认锚点。
7. 根据结果确定路由阈值和 TD-01 结论，再进入 M3。

## 8. M2 完成标准

- 40 页固定样本均有可复现输入、工具版本、配置、原始输出和质量结果。
- 约 20 个条款/文字锚点和 10 个表格/数值锚点经过人工确认或纠正，并覆盖全部主要页面路径与结构难点。
- 每页都得到 `native`、`hybrid_ocr`、`full_ocr`、`skip_blank` 或 `quarantine` 的可解释结论。
- Canonical Document 能保存文字、条款路径、表格、物理/印刷页码和 bbox。
- 失败案例被保留并解释，没有为了得到好看数字而从样本集中删除。
- 最终解析路由由实验批准，而不是由工具流行度决定。
