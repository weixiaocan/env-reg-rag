# M6 总评估报告 v1

## 1. 阶段结论

**M6 通过，但通过范围严格限定为：可演示、可复现、可进入开源准备的企业式单机 POC。**

本结论允许项目进入 P7“开源与面试交付”，不等于生产就绪批准。当前没有验证多用户并发、远程 MCP 认证、异地灾备、可用性目标和真实费率成本，因此**生产就绪判定为未通过**。

M6 的目标不是证明系统没有缺点，而是让每项能力声明都能指向实际证据，并把未达到的能力留在明确限制中。该目标已完成。

## 4. 非阻断限制与后续入口

1. **AI-009 生成完整性**：当前证据三轮均检索正确，但模型两轮未覆盖补充结果“动态管理”。在改写评分规则前，应先人工确认其是核心必答事实还是补充结果。
2. **成本**：已记录 token，但未配置经核实的输入/输出费率，因此不报告金额。
3. **性能**：36 个顺序请求形成的 P50/P95 只是当前机器和模型配置下的基线，不能外推为并发吞吐。
4. **灾备**：已实跑本机卷外备份，但没有异地备份、RPO 或 RTO 承诺。
5. **MCP**：当前是本机 stdio 服务，不是带认证、多租户或限流的远程服务。
6. **开源语料**：代码可开源不等于 PDF 可再分发；P7 必须逐份确认许可边界。

## 5. 可对外声明与禁止声明

### 可声明

- 建立了从文档准入、PDF 解析/OCR、证据单元、混合检索、有据回答到部署恢复的完整 RAG 链路。
- 在当前 12 题 Golden/Answer Set 上，Qdrant RRF 的 Recall@3/5 为 0.8182；三轮 36 请求通过 34 个，无系统错误。
- 所有回答主张必须绑定可引用 evidence ID；公式等未批准转写内容只定位原文。
- 单机 Docker Compose 冷启动、持久化、Qdrant 备份恢复和本机 stdio MCP 已经实跑。

### 禁止声明

- 不得把 34/36 称为“生产准确率 94.44%”。
- 不得声称已完成生产高可用、并发容量、远程 MCP 安全或异地灾备验证。
- 不得把 23 份已盘点 PDF 都说成已批准正式语料。
- 不得报告未配置费率时的模型成本金额。
