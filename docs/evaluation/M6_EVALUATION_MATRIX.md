# M6 分层评估矩阵与验收基线 v1

## 1. 为什么要分层评估

端到端回答错误不能直接归因于大模型。它可能来自文档来源不可靠、PDF 转写错误、正确证据没有被召回、模型没有忠实使用证据，或者服务运行失败。本项目沿用技术规格中的五层框架，分别给出证据和门槛，不使用单一 RAG 总分掩盖问题来源。

本文件区分三类数字：

- **事实基线**：已经由当前版本真实运行得到；
- **发布硬门槛**：来源、隔离、引用等不能妥协的正确性约束；
- **待测门槛**：当前样本不足，先规定测量方法，不伪造 P95、成本或规模承诺。

## 3. 数据与解析层

### 当前证据

- 40 个代表页路由：14 页原生解析、15 页全页 OCR、6 页混合 OCR、3 页 Docling 定向恢复、2 页空白跳过；
- 决策状态：20 页 `approved`、17 页 `needs_manual_review`、1 页 `quarantine`、2 页 `skip_blank`；
- 人工基准：20 个文字/条款锚点、10 个表格/数值锚点，25 个按预填确认、5 个经人工修正；
- OCR 重路径 7 个表格断言中 4 个通过，未通过页面保留复核或隔离状态，而不是降低门槛后发布。

### 失败回路

来源、版本、效力或文件身份失败，回到 M1；文字、表格、条款路径或页码失败，回到 M2。只有重新批准的材料才能生成新的语料版本。

## 4. 检索层

当前 RRF 相比 exact dense 的主要收益出现在 Recall@3（0.8182 对 0.7273）；Recall@5 相同，说明现阶段收益是把相关证据提前，而不是扩大最终五条候选的覆盖。BM25 单独使用的 Recall@1 和 MRR 更低，因此保留混合检索，不将词法检索单独作为主路径。

检索变更必须固定以下变量后比较：Golden Set、语料 manifest、chunk、embedding 版本、BM25 配置、过滤条件和 k。若正确证据根本不存在，标记为 corpus gap，不计入正例召回，也不能用无关命中“填满结果”。

## 5. 回答、引用、追问与拒答层

回答评估先检查确定性规则，再进行人工语义检查：

1. 状态是否等于标注状态；
2. claim 引用是否存在、是否允许用于回答；
3. 数值是否保留单位、表头和适用条件；
4. 回答是否包含测试集规定的关键内容；
5. 冲突、缺条件和语料缺口是否被显式呈现。

当前一次完整模型回归为 11/12，AI-008 因关键词断言失败，随后单独重试通过。这说明功能可达，但尚不能证明模型在完整批次中稳定达到 12/12。M6 下一次模型评估应保存连续完整运行结果，分别报告“单次通过率”和“跨运行稳定率”，不能用挑选最佳一次替代。

## 6. 系统与运维层

### 已执行的测量

- 查询各阶段耗时：条件解析、embedding、Qdrant、模型、结果校验；
- 每次模型调用的 provider、model、token 用量和可计算成本；
- 不少于 30 个代表请求的 p50、p95、最大值和错误率；
- Qdrant、模型配置缺失和超时情况下的就绪状态与稳定错误码；
- 正式语料的发布、撤回、回滚、备份和恢复；
- Docker Compose 冷启动、重启后持久化和依赖健康检查；
- 直接调用、HTTP 和 MCP 对同一固定请求的语义一致性。

上述项目均已执行，但成本费率未配置、并发与远程 MCP 未测试、恢复仅为本机卷外副本。因此仍只能声明“企业式单机 POC 已形成可复现基线”，不能声明生产级吞吐、可用性或异地灾备能力。

## 7. 回归门控顺序

```text
数据身份与准入
  → 页面解析与质量门控
  → 证据单元与检索指标
  → 回答/引用/分支状态
  → HTTP、部署、恢复与 MCP 一致性
```

上游门控失败时停止下游发布：例如页面仍在人工复核，就不应该通过调整提示词让模型“猜对”；检索未召回正确证据，也不应该只用回答评分掩盖漏检。
