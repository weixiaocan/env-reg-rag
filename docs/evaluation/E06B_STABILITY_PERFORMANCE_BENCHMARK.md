# E06B 三轮回答稳定性与性能基准

## 1. 评估目的

单次回答通过只能证明“这一次能答对”，不能证明同一版本能够稳定复现。M6 因此固定 `m4-answer-set-v1`、正式/实验语料版本、Qdrant 检索配置、提示词和智谱模型，对 12 个案例连续执行 3 轮，共 36 个 HTTP 请求。

脚本在每个案例结束后立即保存结果，可从已有进度继续；失败案例照常保留，不能用单独重试覆盖完整批次指标。P50 和 P95 使用 nearest-rank 口径。

## 2. 总体结果

| 指标 | 结果 |
| --- | ---: |
| 完成请求 | 36 / 36 |
| 请求通过 | 34 / 36（94.44%） |
| API 或系统错误 | 0 |
| 三轮全部通过的案例 | 11 / 12（91.67%） |
| 实际模型调用 | 30 |
| 输入 / 输出 / 总 token | 65,599 / 9,339 / 74,938 |
| 估算成本 | 未配置已核实费率，`null` |

3 个条件澄清请求不会进入检索和模型；3 个 `search_only` 请求只进行检索、不调用模型，因此 36 个请求对应 33 次检索和 30 次模型生成。

## 3. 性能分布

| 链路 | 样本数 | P50 | P95 | 最大值 |
| --- | ---: | ---: | ---: | ---: |
| HTTP 请求总耗时 | 36 | 4590.096 ms | 12726.337 ms | 16678.232 ms |
| Qdrant 检索阶段 | 33 | 25.900 ms | 45.101 ms | 58.621 ms |
| 模型生成阶段 | 30 | 5202.667 ms | 12702.430 ms | 16639.645 ms |

结果显示当前长尾几乎全部来自外部模型生成，Qdrant 检索不是主要瓶颈。该结论基于固定的本地单机环境和小型案例集，可作为当前版本基线，不能外推为生产吞吐或并发承诺。

## 4. 唯一不稳定案例：AI-009

问题为“重庆导则的智慧感知建设加分项要求开展哪些监测工作？”，正确证据 `ev_6de4def06fa0cc2273e5fc2b5761ff79` 在三轮中均排在检索首位，说明失败不属于漏检：

- 第 1、2 轮回答均包含水质或水量设备、人工或在线手段以及常态化监测，但没有覆盖证据后半句的“实现动态管理”，被现有关键词规则判为失败；
- 第 3 轮完整覆盖“动态管理”，通过；
- 三轮状态均为 `answered`，引用均包含正确 evidence ID，没有出现无证据主张。

该问题同时暴露两点：模型对长证据的覆盖存在随机波动；当前“所有关键词必须逐字出现”的自动评分也可能把结果性描述和问题直接要求混在一起。现阶段保留原始 34/36 指标，不在看到结果后修改答案集。后续应为答案集增加“核心必答事实”和“补充结果”分层，再由人工复核确认 v2 评分口径。

## 5. 结论

- 条件澄清、拒答、`search_only`、引用白名单和 API 链路三轮均稳定；
- 当前版本尚未达到预先规定的 12/12 全案例稳定门槛；
- 性能样本达到不少于 30 个请求的测量要求，并形成了可复现基线；
- 在优化 AI-009 前，不把 94.44% 描述成“生产准确率”，它只是当前 12 题回归集上的请求通过率。
