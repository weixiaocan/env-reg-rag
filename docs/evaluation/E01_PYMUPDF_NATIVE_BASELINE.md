# E-01A PyMuPDF 原生解析基线报告

## 1. 结论

PyMuPDF 原生路径已对固定的 40 个代表页完成首轮基线。运行过程无页面级异常，但原生文字层不能覆盖当前语料：19 页没有可用原生文字，21 页仅通过“无空文本、无显式坏字符”的表面检查；30 个人工锚点中，只有 5 个能在原生文本中按“去空白后的精确子串”直接命中。

因此本轮只证明 PyMuPDF 适合作为原生提取候选和坐标来源，不批准它单独承担全部 PDF 解析。下一步必须运行 OCR 基线，并对表格、公式、条款层级和水印页作结构化比较。

## 2. 可复现输入与环境

- 固定样本：8 份实验文档、40 个物理页。
- 人工基准：20 个文字/条款锚点、10 个表格/数值锚点，状态为 `human_approved`。
- 解析器：PyMuPDF 1.28.2。
- Python：3.12.14。
- 运行 ID：`m2-native-1.28.2-5fa6311e92ac`。
- 配置哈希：`5fa6311e92aca6d360ed1ead65fb05cb80a0332ebafc403baa3d4ad40180ff5d`。
- 运行命令：`.venv\Scripts\python.exe scripts\run_m2_native_baseline.py --overwrite`。

原始页结果保存在 `data/eval_results/m2-native-pymupdf-1.28.2-v1-pages.jsonl`，每页包含文本、blocks、rawdict、页面尺寸、旋转、元素 bbox、输入 SHA-256、耗时和锚点检查。元数据与汇总分别保存在同目录的 `run-metadata.json`、`summary.json` 对应前缀文件中。

直接命中的锚点为 `TXT-04`、`TXT-05`、`TXT-11`、`TXT-12`、`TXT-17`。所有表格锚点均未以完整、连续、结构一致的形式命中。

这里的“5/30”不是最终解析准确率。当前比较只做去空白后的精确子串判断：它会严格暴露错字和标点差异，但尚未对表格单元格、条款树和 bbox 分别计分。

## 4. 关键发现

### 4.1 清晰扫描页仍需要 OCR

17 个全页 OCR 候选的原生文本全部为空。页面肉眼清楚说明 OCR 输入质量较好，但不代表 PDF 自带可用文字层；这些页面必须进入 OCR 基线。

### 4.2 “表面可读”不等于内容忠实

7 个混合解析候选全部通过简单字符检查，却没有命中任何人工锚点。例如 QX/T 489 的原生输出包含大量符号乱码；GB 55027 的部分页面只抽到了“住房城乡建设部信息公开 浏览专用”水印，没有抽到正文。

### 4.3 合法汉字错字无法靠乱码比例发现

T/CECS 758 的原生输出总体为中文，但出现 `1.0.1→1.o.1`、`混接→棍接`、`入渗→人渗` 等合法字符替换。因为没有 `�`，仅统计坏字符会误判为通过，必须结合人工锚点和后续 OCR 对照。

### 4.4 原生文本不足以恢复表格结构

PyMuPDF 能在部分页面抽到表名、表头和数值，但输出主要是线性文字，未恢复合并单元格、行列坐标、单位继承和总分层级。10 个完整表格锚点均未直接命中，后续必须用 OCR/表格结构模型单独评估。

### 4.5 基线反向修正了一个人工锚点

首轮运行发现 `TXT-11` 在“73%以上”处被错误截断。经继续指令确认后，人工值已补齐逗号后的完整句子；刷新基线后该锚点能够直接命中。原始首轮结果没有被解释成解析器错误。

## 5. 本轮边界

- 已验证：原生页提取、原始输出保存、统一页面字段、bbox 坐标、显式空文本/坏字符检查、人工锚点字面比对和可复现运行元数据。
- 尚未验证：OCR 文字质量、表格单元格恢复、公式、条款树、印刷页码识别、bbox 叠加图、峰值内存和最终页面路由。
- 本轮不批准最终解析路由，也不进入检索、LangChain 或回答生成。

## 6. 下一步

对 17 个全页 OCR 候选和 7 个混合候选运行 OCR 基线，优先比较：中文错字、数字与比较符号、表格结构、水印抑制、条款层级、每页耗时。之后再将 PyMuPDF 坐标与 OCR 结果组合成混合路由候选。
