# E-01B PaddleOCR PP-StructureV3 降级路径 Pilot

## 1. 结论

PP-StructureV3 3.7.0 已成功接入项目的页面级 OCR 降级路径，但本轮结果不支持“所有降级页统一运行完整结构管线并自动发布”。

- 真实冒烟页 `M2-P035` 的人工文字锚点命中，但水印干扰造成第 1.0.3 条重复、错序，最低文字行置信度为 0.634，质量状态因此为 `review`。
- 4 页代表性 pilot 均执行成功，3 页表面质量为 `pass`、1 页为 `review`；6 个严格人工锚点直接命中 2 个。
- 4 页推理总耗时约 513.8 秒。完整表格管线在当前 CPU 环境下较重，不适合无条件应用于所有正文页。
- 简单表格的数值和主要文字基本可读；复杂表格仍出现“竣工→峻工”等关键字段错误；公式页未可靠恢复上标、下标和二维公式结构。

因此下一轮采用三级策略做对照：普通扫描正文走文字/版面轻路径；真正的表格页走 PP-StructureV3 表格重路径；公式和重路径仍不可信的页面进入人工隔离或专项解析。

## 2. 固定环境与配置

| 项目 | 值 |
|---|---|
| PaddlePaddle | 3.3.1 |
| PaddleOCR | 3.7.0 |
| PaddleX | 3.7.2，安装 `ocr` extra |
| 设备 | CPU |
| PDF 渲染 | PyMuPDF，200 DPI，RGB |
| OCR 版本 | PP-OCRv5 中文 |
| 表格识别 | 开启 |
| 文档方向、形变校正、文字行方向 | 关闭 |
| 印章、公式、图表、区域检测 | 关闭 |
| oneDNN/MKLDNN | 关闭；当前 Windows CPU 组合开启时触发 Paddle PIR 属性转换错误 |
| 坐标 | OCR 像素坐标统一换算为 PDF 左上原点 point 坐标 |

模型文件保存在用户级 PaddleX 缓存，不进入开源仓库。原始 PDF 仍受本项目的开源语料门控约束。

## 3. 真实冒烟结果

`M2-P035` 是带水印的扫描条款页：

- 执行成功，1/1 人工锚点命中；
- 识别 11 行，平均置信度 0.951，最低置信度 0.634；
- 推理耗时约 65.3 秒；
- 因最低置信度低于 0.80，状态由原来的宽松 `pass` 改为 `review`。

这证明“锚点命中”和“整页可自动发布”不是同一个判断：一个已知条款正确，并不能证明同页其他条款没有水印错序或重复。

## 4. 四类页面 Pilot

| 样本 | 难点 | 状态 | 锚点 | 表格数 | 耗时 |
|---|---|---:|---:|---:|---:|
| M2-P001 | 全扫描正文 + 降雨等级表 + 水印 | pass | 1/2 | 1 | 174.3 s |
| M2-P006 | 坏文字层 + 单站降雨等级表 | pass | 1/2 | 1 | 121.2 s |
| M2-P024 | 多行公式、上下标和单位 | review | 0/1 | 0 | 111.1 s |
| M2-P036 | 多级指标与合并单元格 | pass | 0/1 | 2 | 107.2 s |

“状态 pass”在这里仅代表文字非空且单行置信度未低于 0.80，不代表人工锚点、表格结构或公式均通过。最终页面批准仍需合并锚点评价和结构评价。

### 4.1 正文与简单表格

M2-P001 正确恢复了 TXT-01 中用户纠正的“（经融化后）降水”。降雨等级表的主要档位与数值也可读，但人工表格锚点是面向含义的核验描述，并非 OCR 原文的连续字面串，所以当前严格子串检查未直接命中 TAB-01。

M2-P006 的正文与表格主要内容可读，TXT-04 命中。TAB-03 同样因为锚点描述与表格扁平化文本格式不同而未通过严格子串检查。

### 4.2 公式

M2-P024 能恢复公式附近的条款说明，但出现单位上标丢失、等号表达和公式二维结构破坏。本轮主动关闭公式识别，因此该页只能作为“文字可搜索、公式不可作为可靠证据”的失败案例，不能批准为正式公式证据。

### 4.3 复杂表格

M2-P036 检出两张表，并恢复表名、表头、地块项目前缀、多数行名和分值；同时存在关键 OCR 错字和字段变形，例如“管网竣工数据资料”被识别为“管网峻工数据资料”。因此 TAB-10 未命中是有效失败信号，不能仅凭高置信度自动放行。

## 5. 当前质量门控

页面解析先给出表面质量：

- 无 OCR 文字：`fail`；
- 任一识别行置信度低于 0.80：`review`；
- 其余：`pass`。

该门控只是第一层。下一轮需合并以下信号形成最终批准状态：

1. 文字/条款锚点是否通过；
2. 表格字段、数值、单位和合并层级是否通过；
3. 公式、流程图等特殊结构是否需要专项解析；
4. 页面耗时和资源是否适合所选路由。

## 6. 下一轮实验

1. 增加不启用表格识别的文字/版面轻路径，与当前重路径在相同正文页上比较耗时和文字质量。
2. 只给 `table`、`clause_and_table(s)` 等页面启用表格重路径；目录、普通条款和参考文献不加载表格模型。
3. 将表格人工锚点从“连续字面子串”补充为字段/数值清单评价，但保留原批准文本，不静默改写人工事实。
4. 对公式页单独验证公式识别；若资源或准确性不合格，正式路由为 `quarantine`，不把错误公式交给检索。
5. 路由和评价口径稳定后，再运行全部 24 个 OCR 降级候选并批准逐页路线。
