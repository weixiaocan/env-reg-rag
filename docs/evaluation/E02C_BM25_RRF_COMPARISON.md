# E-02C Qdrant Dense、BM25、ANN 与 RRF 检索对照

## 1. 本轮结论

在同一份 58 个 Retrieval Chunk、同一版 Golden Set v1 和相同 Top-5 口径下，Qdrant 服务端的 `dense + BM25 + RRF` 是当前三个方案中总体最好的基线：Recall@3 从单路检索的 0.7273 提升到 0.8182，MRR 为 0.6515。但它仍未召回两道“20 毫米落入哪个数值区间”的目标表格，因此不能把混合检索描述为已经解决数字表格问题。

本轮使用的是本地 Docker 中的 Qdrant 1.19.1。稠密向量为 `BAAI/bge-small-zh-v1.5` 的 512 维向量；词法分支为 Qdrant 服务端 `qdrant/bm25`，显式使用 `multilingual` tokenizer；融合由 Qdrant Query API 执行 RRF。每个分支预取 20 条，最终评价前 5 条。

## 2. 可复现结果

| 方案 | Recall@1 | Recall@3 | Recall@5 | MRR | 语料缺口空结果率 |
|---|---:|---:|---:|---:|---:|
| exact dense | 0.5455 | 0.7273 | 0.8182 | 0.6439 | 1.0000 |
| ANN 查询路径 | 0.5455 | 0.7273 | 0.8182 | 0.6439 | 1.0000 |
| multilingual BM25 | 0.4545 | 0.7273 | 0.8182 | 0.5833 | 1.0000 |
| dense + BM25 RRF | **0.5455** | **0.8182** | **0.8182** | **0.6515** | **1.0000** |

## 3. 逐类观察

1. `REAL-001` 的目标证据从 dense 第 4 名提升到 RRF 第 3 名；用户仍需补充“12 小时还是 24 小时”后才能回答。
2. `AI-004` 从 dense 第 2 名提升到 RRF 第 1 名，说明专业词和表格标题的词法信号能补充语义向量。
3. `AI-009` 在 BM25 中退到第 4 名，但 RRF 恢复到第 1 名，说明 dense 能抵消单纯词法匹配的偏差。
4. `REAL-002` 在地域过滤后保持空结果，符合“山西语料尚未收录”的预期，没有用其他地区材料冒充答案。
5. `AI-001`、`AI-002` 在三种方案中都未进入 Top-5。问题文本包含“20 毫米”，原表保存的是 `10.0~24.9`、`15.0~29.9` 等区间；embedding 和 BM25 都不负责执行“20 是否落在区间内”的确定性判断，RRF 也只融合已有名次，不会产生这种推理能力。

## 4. 工程判断

当前可把 RRF 作为默认候选生成基线，但不能把它当作所有查询的最终解决方案。数字区间表格应在后续实验中增加结构化表示，例如保留“统计时段、等级、下限、上限、单位”等字段，并在问题识别出数字条件后执行结构化范围检索；表格原文仍作为引用证据。这样可以把“找候选”和“确定数值落点”分开验证。

ANN 查询路径在当前语料上的逐题名次与 exact dense 一致，没有观察到召回损失。但只有 58 个向量时，Qdrant 可能自动选择全扫描，因此该结果证明的是服务接口和质量没有回归，不是大规模 HNSW 时延结论。

M3 下一步仍按原计划进行：

1. 扩展地域、文种、效力和时间过滤测试。
2. 验证 collection alias 切换与 snapshot 恢复，再批准正式语料版本 v1。
3. 等语料规模扩大后补做独立的 HNSW 性能实验，不用当前小样本虚构性能结论。
