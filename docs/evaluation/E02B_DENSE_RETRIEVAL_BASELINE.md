# E-02B：BGE 中文 Dense 精确检索基线

> 运行日期：2026-09-05  
> 状态：首个模型基线已运行，尚未完成跨模型选择  
> 结果文件：`data/eval_results/m3-bge-small-zh-v1.5-exact-dense-v1.json`

## 1. 本轮回答什么

本轮只验证 `BAAI/bge-small-zh-v1.5` 在固定的58个 Retrieval Chunk 和 Golden Set v1 上，经过 Qdrant 精确 dense 检索后能否找回目标证据。没有启用 ANN、BM25、RRF、reranker、查询改写或回答模型，因此失败可以主要归因于当前 embedding、检索文本与评测标注的组合。

Qdrant 使用 local/in-memory 模式。该模式本身执行 brute-force 精确搜索，可以用于首轮质量基线；它不能替代后续 Docker 服务进程上的 `exact=true`、持久化和恢复验证。

## 2. 固定配置

- 模型：`BAAI/bge-small-zh-v1.5`
- revision：`7999e1d3359715c523056ef9478215996d62a620`
- device：CPU
- query：添加官方中文检索指令
- document：不添加指令
- pooling：CLS
- normalization：L2
- vector dimension：512
- distance：cosine
- top-k：5
- Golden Set：v1，共12题；其中11题有目标证据，1题为山西语料缺口

## 4. 关键失败

`AI-001` 和 `AI-002` 的目标表格均未进入前5。两题分别询问24小时和12小时降水量20毫米所属等级；dense 检索优先返回了“降水量按24h、12h两个时间段划分”等概念段落，而包含具体数值区间的表1没有进入前5。

这说明：

1. OCR 和表格文字已经存在，问题不是“数据没有抽出来”；
2. 当前使用精确全扫描，问题不是 ANN 近似召回丢失；
3. 单独依赖 dense embedding 对数字、区间、时段列名和表格行的精确匹配仍不可靠；
4. 下一步应验证中文词法/BM25，再用 RRF 判断它能否补回这两题，而不是先调整提示词或接入回答模型。

`REAL-001` 的目标表格位于第4名，符合 Recall@5，但不足以支持最终问答直接只取 top-3。该题本身还要求系统追问统计时段，属于后续 M4 的状态判断，不在本轮 dense 指标中混测。

## 5. 截断风险

58个 chunk 中有5个超过模型512-token输入上限，最长观测为619 tokens。本轮模型已按512截断，因此当前结果包含截断影响。后续需要分别检查这5个 chunk：优先判断证据单元是否过大或表格文本是否应该构造更适合检索的派生视图，不能静默提高上限或只更换大模型。

## 6. 当前结论与下一步

- BGE 已证明本地中文 dense + Qdrant exact 基线可以完整运行，但尚未达到可批准的检索覆盖。
- 原文定位题 `AI-010` 位于第1名，证明 `source_locator_only` 单元可被检索，同时仍受使用策略限制。
- 地域过滤使山西语料缺口题返回空结果，证明结构化 scope 过滤有效。
- 下一步按相同语料和问题验证 Qdrant 中文词法/BM25；随后运行 dense + sparse RRF，重点观察 AI-001、AI-002 和5个截断 chunk。
- E5 与 GTE 仍是 dense 对照候选；只有跑完同口径结果后才能批准最终 dense 模型。
