## 2. SSE 决策

首版不启用 SSE，继续使用 `POST /api/v1/queries` 返回完整结构化 JSON。

原因：

- 当前回答必须在完整生成后执行 evidence ID、冲突和引用完整性校验；提前流出文本可能展示尚未通过证据门控的内容；
- SSE 只能改善等待感，不能直接消除已经观测到的模型长尾；
- 首期调用者包括网页、脚本和后续 MCP，完整 JSON 的一致性与复现成本更低；
- 当前人工体验已可完成问答、追问和原文核验，不需要为首版增加流式状态机。

M6 将测量端到端时延、超时和并发行为。如果长尾仍显著影响使用，再对比“阶段事件流 + 最终已校验结果”，并单独验证断连取消与最终结果一致性。

## 3. M5 结论

M5 通过阶段门槛：网页与直接 HTTP 调用复用同一个查询核心，语义状态一致，用户能够从结果回到文档、条款和物理页完成核验。
