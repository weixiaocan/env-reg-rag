## 1. 已完成

### 分块前主链路

PDF → `build_corpus.py`（来源登记、逐页版面分析、正文/表格/公式/图片四类处理、page-intermediate）→ `assemble_corpus_v2.py`（V2 Canonical）

- 公式缓存缺失时装配硬失败，不会静默产出 0 个公式。
- 处理状态与质量状态分开：执行完成不等于内容正确。
- 扫描件正文由三路识别投票（两路独立 OCR + 版面识别结果）。
- 人工或 agent 对照原页的核对结果登记在 registry，装配时按原识别内容的哈希绑定：
  - `data/registry/source-corrections.json`：公式与文字更正；119 个计算公式经负责人核对，91 个行内单位/化学式片段经 agent 对照原页核对；
  - `data/registry/table-checks.json`：239 张表格逐格核对。
  原识别内容变化时绑定失败，必须重新对齐，不会把旧结论套到新内容上。

### 分块后问答链路

V2 Canonical → `ingest_corpus_v2.py`（分块 + bge-small-zh 向量 + BM25 → 不可变 staging collection，`--publish` 切换 alias `corpus_v2_live`）→ FastAPI 查询 → 浏览器工作台（对话、引用、逐页原文与高亮）

- 依赖：Qdrant、本地 embedding 模型、任意一个已配置的 LLM（未配置时提问只返回原文）。
- 公网演示：`https://weixiaocan.com/rag/`，部署方式见 `deploy/README.md`；数据包随 GitHub Release 发布，只保留当前版和一个回退版。

### 新增 PDF 时的现状

- `build_corpus.py` 扫描整个 `data/raw`，未变化的页面复用阶段缓存，只有新文件实际解析。
- `ingest_corpus_v2.py` 对该语料版本整库重新分块、嵌入，写入新的不可变 collection；按 chunk 增量 upsert **尚未实现**。千页级体量下整库重建可以接受，不要宣传成增量入库。
