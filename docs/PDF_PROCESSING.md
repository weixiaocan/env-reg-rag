# PDF 数据处理修正方案

方案已批准；2026-09-16，统一四类处理方案于2026-09-18确认。下文保留阶段性历史证据；基础文字建库、旧公式批次或固定样例通过均不代表完整PDF处理完成。本轮存量全量处理及增量验收结果另行记录，不声称生产就绪。

统一入口为 `scripts/update_corpus.py`，默认启用逐页本地版面分析及正文、表格、公式、图片分派。`--text-only` 仅供旧文字流程诊断，默认结构并发为1。匹配配置的正文、版面和公式结果可复用，但旧基础approved状态不能用于跳过版面分析。阶段缓存含模型文件校验和、软件版本、DPI及规则；失败阶段可重试，处理执行状态与质量状态独立。

图片只使用原图、原文图号/图注及明确引用图号的正文构建本地检索表示。无图注、歧义关联、未找到脚注或参数说明均逐文件/物理页/区域记录；不调用外部视觉模型，不生成AI图片描述。公式优先原图、原文说明和出处。表格保留行列、合并单元格及模型恢复的表头角色；未可靠恢复的结构不能升级成正式回答依据。

检查点在 `data/model_runtime/unified_pdf/`，候选全量完整性报告在 `data/canonical/<版本>-structure-audit.json`。运行 `python scripts/audit_unified_pdf.py` 可核对所有主文本页，缺页也逐页列出；`--canonical` 可核对指定候选制品。核对包含来源SHA、区域账本、原PDF重渲染裁剪图及独立原页公式锚点漏检检查。固定锚点不代表全库漏检率或内容准确率。未处理锚点页单列，不冒充已评测漏检。

未核验结构仅生成source_locator_only，保留区域、关系及原图身份，检索命中后通过 `/api/v1/regions/<区域ID>` 和 `/image` 阅读原图及原文。新候选版本绑定实际输出和完整性报告；失败重试产生不同不可变版本。发布前验证完整性报告和制品摘要，并保存旧指针及别名目标到版本rollback记录；旧集合保留。全量候选尚未通过时不得切换正式库。

## 当前可用：离线来源审计

先通过 `scripts/update_corpus.py --plan-only` 刷新文件清单，再运行：

```powershell
.venv\Scripts\python.exe scripts\audit_pdf_sources.py
.venv\Scripts\python.exe scripts\audit_pdf_sources.py --write
```

第一条为只读预览；第二条生成 `data/registry/source_evidence.jsonl` 和 `data/registry/pdf_source_audit.json`。增加 `--details` 可查看逐文件字段与疑点。它不联网、不改 PDF、不运行 OCR、不发布索引、不切换现有问答库。

来源记录以完整 SHA-256 关联内容，保留改名前后的路径记录。每个 observations 项包含 field、value、origin_kind、status、evidence_ref、checked_at、verification_method。旧 CSV 导入为 legacy_record/unverified，保留原始值、原表相对路径、行号和行内容摘要；不会补造核验日期，也不把历史 official_fulltext_verified 标记自动升级成新核验。

从前3页可用文字层中有限提取标准编号与“发布/实施”日期，记录原页哈希、物理页码和匹配原文；同样属于待核验声明。扫描页不能靠这一步自动补齐字段。提供者声明可登记为 provider_declared；经过实际比对的信息可登记为 external_verified 或 document_extracted 的 verified 记录，必须提供有效依据、带时区的核验时间与方法。程序校验这些记录的结构，不代替实际比对。

同一字段的多份观察值全部保留。已核验值优先于未核验声明；多份已核验值冲突时不挑选赢家。核验时间是实际执行检查的时间，不是文档发布日期。旧 CSV 保留不动；后续审计不会删除人工登记的观察值。

完整性检查覆盖逐页可读性、与登记页数/已核验预期页数的差异、原生文字中可发现的节选标记和底部连续页码疑点；记录目录、附录和草稿线索。readable_page_count 只表示解析器能够读取页面，不表示扫描文字已识别。页码和标记检查属于启发式，不能证明完整性或自动拼接跨页内容。

完整性状态：unverified（没有充分证据）、suspected（发现疑点）、evidence_supported（存在已核验的全文比对记录，且检查未发现冲突）。页数一致本身不能进入 evidence_supported。完整性仍未知不阻止资料解析，也不按版权状态剔除资料。

有来源登记表时，后续建库按哈希读取它，不再按文件名继承批准。旧审批及效力值保留在历史字段；缺少新核验时 source_review 为 needs_review、effective_status 为 unknown。未迁移时兼容旧 CSV 值，但额外标明 legacy_unverified。实际来源字段的逐项状态和摘要写入文档元数据，参与候选库版本指纹；不更改既有文档/证据 ID。

完整性报告仅在来源登记的字节摘要和 inventory 的结构化内容摘要均匹配时用于后续建库；清单换行符变化不会误判为新内容，过期报告不会沿用。来源 JSONL 固定 LF，CSV 行号表示包含表头的逻辑记录序号。两文件分别原子写入，不支持多管理者并发修改；中断或人工修改后重跑审计恢复一致性。报告可能包含历史声明分歧，不能解读为官方资料一定有错。

此阶段不包含管理页面或自动官方核验。来源登记及主文本选择已在2026-09-16的全量更新中应用；来源证据仍待核验，不因发布而升级。

需求依据：本轮讨论确定的四个修正方向。现状见 [架构说明](ARCHITECTURE.md)。基础实现采用 PyMuPDF、PaddleOCR、逐页缓存和不可变语料发布；未证明能在上万份资料规模满足容量要求。

## 1. 范围与约束

### 当前可用：文档版本与主文本选择（PDF-01）

`scripts/review_document_relations.py` 只读输出精确重复组、同版本候选和已登记关系；`--compare SHA256_A SHA256_B` 比较两份已登记文件的原生文字，保存逐页文字摘要并输出有限字符范围的5字符片段相似度。比较不联网、不OCR、不写文件；扫描页或截断时相似度与文字等价为未知。即使全部原生文字一致，也不能据此证明图像、表格和公式等价。

`data/registry/document_relations.json` 格式为 `schema_version: "1"` 和 `relations` 数组。状态支持 candidate、conflicting、confirmed；前两种只报告，不影响入库。完全相同的文件仍由 inventory 按SHA-256去重，无需另登记逻辑版本关系。

确认一组不同文件需提供：

- document_id、document_version_id：稳定的英文字母/数字/连字符/下划线身份，不改变现有哈希文档ID。
- identity：document_kind、source_authority、revision；标准另外需要含年份的standard_number，其他资料需要title、publication_date。
- member_sha256：所有被全文比对的完整文件哈希；primary_sha256必须在其中。
- checked_at：实际复核时间，ISO格式并包含时区。
- comparison：method固定为manual_full_document_comparison，result只能为layout_only或identical_body，compared_sha256必须覆盖全部成员，note说明实际比对依据和差异。字段合法性检查不能替代真正的全文复核。

已核验的source_review=official_fulltext_verified且official_source_uri已核验的成员优先成为主文本；文件名含official、文件夹位置或旧核验标记不能使不同哈希的内容自动获得优先权。多个官方成员时保留已指定官方主文本，否则按哈希稳定选择。主文本的来源与质量批准不会从另一份副本继承，主文本选择也不授予正式回答权限。

确认记录引用缺失/变更的哈希、关系重叠、版本编号不一致、身份核验证据冲突或实质正文差异时，构建失败而不是静默排除资料。更正后可重新构建候选；不修改已发布指针。新文件哈希必须重新确认，不能按旧文件名继承关系。

候选清单和manifest区分source_file_count（物理文件）、unique_content_count（独立字节内容）、duplicate_copy_count（精确副本）、selected_content_count（待解析主文本）、same_version_copy_count（确认后省去的不同字节副本）。关系及文件映射参与语料版本指纹；manifest保留旧哈希文档ID、逻辑身份、原始副本路径及主文本哈希。副本到新主文本的页码映射标记not_established，旧引用仍需其原版本语料，不能自动重定向到新排版的同页。

## 2. 选择与取舍

### 文档合并

保留 SHA-256 精确文件去重；新增文档身份和版本关系。标准使用标准编号（含年份）、修订信息、发布机关等字段；其他资料使用名称、机关、日期和类型生成候选关系。标识冲突或缺失时不自动合并。

正文相似度只用于发现候选和定位差异，不作为删除或批准依据。相比仅按编号合并，更安全但增加复核工作。确认只是水印、封面或排版差异后选择主文本；正文实质差异必须解决或标记冲突。不同年份或修订版不能合并成同一版本。

### 来源核验

优先使用已有可靠记录和提供者附带依据；必要时由使用者明确触发外部核验。相比每次自动下载，减少成本、误匹配及网络依赖。文件清晰度不等于来源可靠或完整。

### 解析工具

保留现有原生提取和 PaddleOCR，困难区域升级到版面、表格和公式识别。先针对代表性页面评测，不预先认定优于 Unstructured。公式识别模型加载失败或效果不足时保留原页定位，不伪造转写。

### 公式原文展示

优先展示原PDF公式图片，并保留编号、用途、参数、单位、适用说明及明确跨页关系的原文依据。现有局部核对登记与全量自动识别分开；缺失和不确定项逐区域记录，不推断原文未列明的含义或单位。本轮功能范围不含计算器。

## 3. 流程与数据

原件登记 → 文档身份/版本候选 → 主文本确认 → 逐页解析 → 区域结构识别 → 单项质量复核 → 证据与检索块 → 候选库校验 → 版本发布。

原件不可覆盖。区分 file_asset_id（文件哈希）、document_id（资料身份）、document_version_id（逻辑版本）和 processing_revision（处理配置与算法版本）。新的逻辑身份不能简单替代旧哈希 ID，必须提供映射。

审核记录迁移到稳定身份/文件哈希关联，文件名只作为显示字段。每个来源或版本字段保存 value、origin_kind（提供者声明/文件内提取/外部核验）、evidence_ref（URL 或文件哈希与页码）、核验时间和状态；允许多份证据或冲突记录。

完整性状态为未核验、存在疑点、有证据支持。内部检查覆盖可读性、目录/附录/页码断裂等；“没有发现异常”不能升级为完整性已证实。无需或无法联网的资料保留状态，不仅因未核验而自动阻断解析。

同一版本包含主文件和其他文件关系；主文件候选 → 待确认 → 已选定/冲突。只有已确认关系参与去重发布。既有内容不因候选关系被静默排除。

页面保留基础质量状态；新增区域级状态，避免一个公式问题隔离整页正常正文。结构状态为已识别 → 待复核 → 已批准/原页定位。自动筛查通过不等于人工复核。

表格保存区域坐标、行列与合并单元格、表头、单位、脚注及跨页候选关系；跨页拼接需证据支持。关键数字绑定来源单元格或文本区域，不孤立保存数值。

公式保存原页区域、公式编号、原始转写、标准化表达、变量定义、单位、适用条件、相邻条款、识别配置与复核状态。变量定义可能在其他页；未找到时明确缺失，不由模型补造。显示 LaTeX 与可执行表达分开。

## 4. 模块接口与失败边界

- 资料关系解析：输入文件清单、来源证据与已确认关系；输出待处理内容及身份映射。隐藏候选比较和主文件选择，冲突不能静默覆盖。
- 页面/区域解析：输入页面、处理配置和缓存；输出标准化区域及质量信息。隔离不同识别路线、模型加载与资源限制；通过固定页面夹具测试。
- 质量核验：输入区域及支持记录；输出批准或定位权限及原因。针对表格、数字和公式分别核验；低置信度、多解析器一致都不单独构成正确性证明。
- 公式服务：输入已登记公式身份和明确的变量；输出计算步骤、结果、单位和引用，或缺失/非法/不支持状态。网页、HTTP 和 MCP 复用同一服务。

超时和异常按区域/页面保存；有限重试后记录失败，模型配置改变后重处理。新增受控重处理入口，不能无限复用旧失败缓存。仅重处理受影响结果，未批准内容只提供原页定位。

计算只允许登记表达式、函数和变量；禁止 eval、动态导入、文件/网络访问及任意模型代码。校验有限数值、取值范围、单位转换、分母为零和适用条件；缺少输入时追问，不猜数。用户确认公式选择和输入单位后执行。

## 5. 生命周期、安全和发布

既有审核表作为 legacy 导入，保留原值但不得伪造缺失的证据和日期。提供 dry-run 迁移与旧 ID 映射，不破坏已有引用或黄金题集。

处理结果、模型/配置、关系表和质量决策参与版本指纹。新流程使用独立候选库；哈希、数量、引用和权限通过检查后切换，保留旧指针与 collection 供回退。更换主文件必须重新核对证据定位和审批有效性。

默认本地解析；外部传输原件需要明确选择。联网核验限制协议、允许的主机、重定向、大小和超时，防止访问内部地址；不把密钥、个人信息、绝对本机路径写入公开记录。

更正/下架时处理原件、转写、证据、索引和缓存，旧版/备份不能继续提供被删除内容；与 DATA_NOTICE.md 的流程一致。

记录文件/页面/区域与处理版本，统计候选重复、冲突、缺失依据、结构待复核、耗时、错误和资源占用。先测代表性资料，再估算批量吞吐；不凭并发数宣称支持上万文件。

## 6. 验证策略

确定性测试：同字节异文件名、同版本异排版、不同版本、正文冲突、缺失身份；来源字段出处与冲突；缓存中断恢复与失败重处理；旧引用映射；发布与回退。

建立人工金标准页面集，覆盖原生/扫描/混合 PDF、合并表头、跨页表格、单位脚注、负号、小数点、范围边界、分数、上下标和分段公式。原页与转写逐项比对，标注者看原件而非模型输出。

识别评测分别记录正文错漏、关键数字/符号准确率、表格单元格与表头对应准确率、公式结构正确率、变量/单位覆盖和复核工作量。建立基线后共同确定发布阈值，不能预先承诺全面准确。

允许计算的每一条登记公式必须有人工批准记录及金标准算例；覆盖正常、边界、非法、缺失输入、单位转换和异常数值。精度/舍入遵循原文，未规定时显式展示约定。允许误差逐公式规定。

端到端检查：问公式 → 展示公式与变量和引用 → 补充输入 → 确认 → 返回确定性结果；未验证公式仅定位，不执行。验证不同接口一致。
