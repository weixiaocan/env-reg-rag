# 环保法规规范证据助手——产品规格

## 文档控制

- 状态：Approved v1.0
- 修订日期：2026-09-03
- 相关输入：`docs/DOMAIN_LANGUAGE.md`、`data/inventory.csv`
- 说明：本文定义产品问题、范围和验收意图，不定义技术架构与具体实现。

## 1. 问题与背景

排水监测、咨询、设计和运维人员需要频繁从法律法规、标准、导则、政府政策、工作方案和行动计划等规范性文件中查找工作依据。现有的人工查阅方式存在四类主要风险：定位耗时、引用难以回查、文档版本或地域适用性混淆，以及把经验判断误当成规范要求。

本项目提供一个面向环保领域法律、法规、标准和技术规范的证据助手。用户提出工作问题后，系统应优先返回可定位、可回查的规范证据；只有在证据充分时才形成受证据约束的回答。资料库可以按同一准入、解析、检索和发布机制持续扩展。系统不替代工程师、审查人员或法务作出专业判断。

项目当前以求职面试为交付优先级，但产品问题、数据限制和评估结果必须按真实情况表达。它可以模拟企业项目流程，不能虚构真实企业用户、同行验收或生产运行数据。

当前项目拥有 23 个 PDF 文件，但资产审计表明，其中包括需要 OCR、来源记录缺失、重复副本、预览版和征求意见稿。因此，“已有 23 份可直接作为正式依据的权威文档”不是已确认事实。

## 2. 目标与成功信号

### 2.1 产品目标

1. 缩短工程人员定位规范依据的时间。
2. 降低错引文档版本、条款位置和地域要求的风险。
3. 让回答中的重要主张能够回查到具体证据。
4. 在证据不足或问题越界时给出可理解的受控结果，而不是猜测。
5. 形成可供人工使用，也可被其他 AI 应用复用的稳定证据能力。

### 2.2 首期成功信号

- 代表性真实问题能够找到正确证据，并且用户可以回查原文。
- 相比人工翻阅，完成一次条款定位所需时间明显下降。
- 文档版本、地域、条款位置或来源不确定时，系统会明确暴露不确定性。
- 没有足够证据的问题不会被包装成确定的规范结论。
- 每次产品变更都能在同一组问题上复测并解释结果变化。

具体数值门槛不沿用旧 PRD 的占位值。先建立人工基线和最小检索基线，再在试点前确定验收阈值。

## 3. 用户与干系人

### 3.1 主要用户

- 排水监测工程师、咨询工程师和排水数据分析师

### 3.2 次要使用方

- 需要为监测分析结论查找规范依据的数据分析 Agent
- 排水设计、运维和项目审查人员
- 需要了解概念和依据的新人工程师

### 3.3 项目角色

- 产品、领域判断与验收：项目维护者
- 技术开发与测试：项目维护者与 AI 协作完成
- 责任边界：这是单人面试项目，不宣称经过独立同行或企业验收

## 4. 代表性工作流

### W-01 自然语言查找依据

工程师描述一个排水业务问题，查看相关条款证据及其来源、版本、位置和适用性信息，并回查原文。

### W-02 精确定位

工程师输入标准号、文档名称或条款号，直接定位指定文档版本和条款；不存在或版本不明时得到明确提示。

### W-03 数值或表格证据查询

工程师查询阈值、等级或计算条件，结果保留数值对应的时间尺度、表头、单位、注释和适用条件，避免孤立返回一个数字。若问题缺少决定数值含义的条件，系统先提示歧义或展示不同条件下的定义，而不是任意选择一个标准。

### W-04 证据不足或问题越界

当语料未覆盖、版本无法确认、地域或时间条件缺失，或者用户要求系统直接作出合规结论时，系统说明不能形成结论的原因，并提示需要补充的信息或人工复核动作。

### W-05 跨文档差异比较

工程师选择或指定多个文档版本，查看它们针对同一事项的要求及适用范围差异。例如，对同一个监测或设计问题，分别列出国家标准与地方导则的原文、条件和适用地域。系统只对齐和展示差异，不替用户判断哪一条适用于具体项目。该工作流为基础证据检索完成后的增强项。

### W-06 新增或更新规范性文件

维护者提交新的规范性文件或新版本。系统在进入正式可检索语料前检查来源、版本、状态、适用范围、完整性和解析质量；不满足要求的材料进入待补充或隔离状态。发布后，新语料版本可被查询和追踪，出现问题时能够撤回。

### 4.1 用户提供的真实需求锚点

以下问题来自既往排水工作经验，用于验证产品需求是否贴近实际工作；它们不是完整 Golden 测试集，也尚未在本阶段标注答案。

1. “雨量在 20 毫米的时候属于什么降雨等级，是中雨、大雨还是小雨？”
   - 暴露的产品需求：系统需要识别降雨量对应的统计时段和所用标准；缺少时段时不能直接给出唯一等级。
2. “山西省关于雨污混接的政策文件规定了要开展哪些工作？”
   - 暴露的产品需求：语料必须覆盖政府政策、工作方案和行动计划；结果需要呈现发布机关、适用地域、发布时间、工作对象、要求采取的行动及原文依据。

后续由 AI 生成的普通、边界和对抗问题必须标为“生成问题”，不得与上述真实需求来源混写。

## 5. 需求与验收标准

| ID | 优先级 | 产品需求 | 可观察的验收标准 |
| --- | --- | --- | --- |
| R-01 | Must | 支持用自然语言查找规范证据 | 对一组已人工标注的代表性问题，系统返回候选证据；每条结果展示可阅读原文及可回查定位信息，效果通过统一评测集记录 |
| R-02 | Must | 支持按文档名称、标准号和条款号精确定位 | 对已收录的有效定位能够返回对应条款；不存在、未收录或版本不明确时不伪造结果 |
| R-03 | Must | 回答中的规范性主张必须受证据支持 | 用户可以从每个重要主张查看其支持证据；抽样复核时不得用模型常识补全证据中不存在的规范要求 |
| R-04 | Must | 展示文档版本和适用性信息 | 结果展示已知的发布机构、版本、状态、地域和时间信息；未知字段明确标为未知，不猜测 |
| R-05 | Must | 保留数值和表格证据的解释上下文 | 返回数值时同时展示能够决定其含义的单位、表头、注释和适用条件；缺失上下文时不得单独给出确定结论 |
| R-06 | Must | 对证据不足和越界问题提供受控拒答 | 测试集中未覆盖、条件不足和要求合规判定的问题得到对应原因，不生成确定性规范结论 |
| R-07 | Must | 引用能够回查正式材料 | 每条作为依据使用的证据至少提供文档版本、条款或结构位置、页码或等价定位，以及已登记的来源信息 |
| R-08 | Must | 查询过程可以复现和审查 | 对一次已保存的查询，可以看到输入、使用的语料版本、返回证据和最终结果；不得只保留最终回答文本 |
| R-09 | Should | 用户能够查看当前可用的文档版本 | 可以按主题、地域、类型和状态查看收录范围，并区分正式语料、历史版本和隔离材料 |
| R-10 | Should | 支持跨文档差异比较 | 完成基础证据检索后，给定同一问题和指定文档集合时，分别展示各文档证据和适用范围，不把差异自动解释为合规结论 |
| R-11 | Should | 证据能力可供其他 AI 应用复用 | 数据分析 Agent 能获取结构化证据结果；具体协议和接口形式留待技术设计 |
| R-12 | Must | 支持受控地新增、更新和撤回文档版本 | 新材料只有通过来源、版本和质量检查后才进入正式语料；发布记录可追踪，失败材料不污染当前可查询版本，已发布版本能够撤回或回滚 |
| R-13 | Must | 识别影响答案成立的缺失条件 | 对降雨量时段、地域、适用时间、对象等关键信息缺失的问题，系统明确指出歧义并请求补充，或分别展示不同条件下的证据，不擅自选定条件 |
| R-14 | Must | 提供桌面优先的证据核验工作台 | 用户在同一页面阅读回答和核验证据；关键主张后有内联引用，点击后显示对应原文、条款、页码、版本、发布机关、地域、日期、效力状态和来源入口 |
| R-15 | Must | 自动识别并展示当前查询的适用范围 | 系统从问题和对话中识别地域、时间、对象及文件层级，优先检索适用的地方文件并补充国家层级依据；每条证据明确标注地方或国家属性。关键条件不明确时通过对话追问，不要求普通用户操作高级筛选 |
| R-16 | Must | 没有可靠综合答案时仍可查看搜索结果 | 证据不足时不生成无引用的确定结论，但用户仍能查看相关文档和原文片段，并了解为什么没有形成答案 |
| R-17 | Should | 提供结构化问题反馈 | 用户可以区分回答错误、引用不支持、漏检文档、版本/效力错误、问题理解错误和回答有帮助；反馈关联到可复现查询记录 |
| R-18 | Should | 支持受控的上下文追问 | 用户可以补充时间尺度、地域、文档范围等条件；界面显示本轮继承的关键条件。首期不扩展为无边界的通用聊天记忆 |

## 6. 非功能要求

| ID | 类别 | 要求与验收意图 |
| --- | --- | --- |
| NFR-01 | 可信性 | 正式结果只使用已登记并允许进入当前语料版本的材料；来源不明、预览版和征求意见稿默认隔离 |
| NFR-02 | 可追溯性 | 文档更新、语料发布和查询结果能够关联到明确版本，支持复查历史结果 |

| NFR-06 | 成本 | 能记录主要模型调用与处理成本，并在效果、速度和成本之间给出可解释取舍 |

## 7. 范围边界

### 7.1 已确认的首期 POC 范围

- 聚焦城镇排水管网的雨污混接、入流入渗、监测评估及紧密相关设计依据。
- 收录对象包括相关法律法规、国家/行业/地方/团体标准、技术导则，以及政府发布的政策文件、工作方案和行动计划。
- 支持条款定位、自然语言证据检索、数值与表格证据、带引用回答和受控拒答。
- 使用少量来源与版本可核验的种子文档证明完整闭环。该数量只用于验证流程，不代表最终产品语料规模。
- 提供最小人工使用入口，并为后续 Agent 接入保留结构化结果。

### 7.2 POC 后的数据扩展范围

- 增加更多排水规范性文件和文档版本，逐步扩大问题覆盖面。
- 建立新增、更新、隔离、发布和撤回的受控数据流程，避免每次依靠人工改数据库。
- 让合格文档经过处理后进入新的可查询语料版本，并保留全过程状态和失败原因。
- 在核心证据能力稳定后，以服务形式供其他数据分析 Agent 调用；MCP 是候选适配协议，具体选择留待技术设计。

### 7.3 首期不做

- 不判断具体工程、方案或监测结果“合规/不合规”。
- 不替代注册工程师、审查人员、监管人员或法务意见。
- 不把联网搜索到的未经登记材料直接作为正式规范结论。
- 不承诺覆盖全部环保法规或全部排水规范。
- 不做自由多轮通用咨询、自动审批或自动生成正式审查意见；只支持围绕证据核验和条件补充的受控追问。
- 不以复杂前端、高并发或多供应商切换作为首期产品成功标准。
- 不把面试展示效果置于业务真实性和证据可靠性之上。

### 7.4 后续可能方向，不构成承诺

- 扩展到其他水务或环保主题。
- 纳入受控企业手册并继承企业权限。
- 与排水监测数据分析 Agent 深度集成。
- 增加用户反馈、在线评估、更新提醒和运营能力。

## 8. 风险、假设与依赖

| 类型 | 内容 | 失效条件或应对 |
| --- | --- | --- |
| 已确认约束 | 首期使用可以从公开渠道收集的规范性文件；已确认来源的材料允许调用公有云模型 | 若引入内部材料，暂停入库并重新确认权限、部署和外部模型调用边界 |
| 假设 | 项目维护者能够提供真实排水工作问题并完成首轮领域判断 | 若没有真实问题，只能声明为技术演示，不能宣称验证了业务价值 |
| 风险 | 现有 PDF 数量不等于可用语料数量 | 先验证来源、版本、完整性和解析质量，宁可减少种子文档 |
| 风险 | 标准版本和适用性信息可能无法从 PDF 正文可靠获得 | 将权威来源登记作为正式发布前置条件，未知状态不得自动推断 |
| 风险 | 单人标注产生确认偏差 | 保留标注依据、区分真实工作问题与 AI 生成问题，并在项目说明中明确没有独立同行验收 |
| 依赖 | 需要能够回查的官方来源或受控来源记录 | 无法核验来源的材料只能隔离用于实验，不能进入正式结果 |

## 本次修订相对旧 PRD 的主要变化

- 将“泛排水法规库”收敛为已确认的排水专题首期范围，并明确 POC 后继续扩充语料。
- 不再把 23 个 PDF 等同于 23 份可用权威语料。
- 删除缺少基线支持的固定准确率、召回率和延迟承诺。
- 将主要业务主张与证据映射、数值上下文和查询复现写成可观察要求。
- 把具体框架、向量库和可插拔组件等技术选择移出产品规格；仅保留“可供其他 AI 应用复用”的产品要求，MCP 作为后续技术设计候选。
- 明确排水监测、咨询工程师和分析师为主要用户，数据分析 Agent 为次要调用方。
- 新增文档版本的受控接入、发布和撤回要求。
- 纳入政府政策、工作方案和行动计划，并用两个真实工作问题校准数值歧义与政策检索需求。
- 根据成熟产品一手资料，将首期入口收敛为桌面优先的证据核验工作台，并补充范围控制、搜索降级、结构化反馈和受控追问要求。
- 根据原型反馈取消主问答入口的高级筛选和 ABC 布局切换，确定连续对话、右侧证据、展开原文与搜索降级的一体化界面。
