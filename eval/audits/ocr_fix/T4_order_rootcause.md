# T4 阅读顺序根因证据

## 确定性根因

- `src/application/canonical_assembly.py:389` 起的 `assemble_document` 在页内收集 item 后调用 `detect_columns`，再按其 `reading_order` 形成全局元素流；section_path 随该流逐项推断，因此排序错误会直接变成归属错误。
- `src/ingestion/column_detection.py:149` 起的旧判定只要求非满宽 bbox 的横向中心形成足够大的间隙，未验证左右组之间是否存在真实的空白列缝。p25 的缩进首行、左边距短续行、居中标题/布局框形成两个中心簇，但 bbox 横向重叠，仍被误判为 2 栏。
- 旧布局随后执行左栏全部自上而下、再右栏全部自上而下，短续行被整体前移；heading 栈在错误顺序上运行，于是续行继承了先前的 `6.1.6`。
- `src/ingestion/column_detection.py:175` 的修复增加真实边缘列缝门槛：`min(right.x0) - max(left.x1) >= 0.02 * page_width`。p25 横向重叠，不再允许 column-major 重排。
